## 本轮修的 bug：中断后旧回合会"复活"（严重）

**现象（用户操作序列）**：按 Esc 中断 → **紧接着**又发一条 → 两个回合同时在跑。

**根因**：`session.cancelled` 是个**共享布尔值**。`protocol.mjs` 的 `send_message` 在开新回合前
会把它置回 `false`，而被中断的那个回合正卡在 `await chatCompletion(...)` 上 ——
等它回来时 `cancelled` 已经是 `false`，于是**复活**，和新回合并发：
两边都往同一个会话写消息，被中断那一轮的工具继续执行（写文件、跑命令），用户以为已经停了。

**实测证据**：
- 内部探针（桩模型）：中断后 msg_old 事件 11 → 22 条，最终产出 **20 个工具调用**、以 `turn_complete` 收尾。
- 真实 API + 真实 WS 协议（旧代码，8799）：中断后工具调用 **7 次仍在增长**、无终止事件。
- 同一探针对新代码（8798 隔离实例）：**工具调用停在 1 次**，以 `turn_cancelled` 收尾。

**修法 —— 回合代次**（`web/server/sessions.mjs`）：
```js
beginTurn(session)      // 回合开始：代次 +1，返回"我这一代"
cancelSession(session)  // 中断：cancelled = true 且代次 +1（让在途回合立刻过期）
turnExpired(session, s) // 代次对不上 = 已过期
```
- `engine.mjs` 里所有 `session.cancelled` 判定换成 `expired()`（含子代理与 emit 包装器）。
- `deleteSession` 与 `protocol.mjs` 的 `cancel` 都改走 `cancelSession`。
- 代次是**运行时状态，不落盘**（跨进程沿用旧代次没意义）。

## 本轮修的第二个问题：定时任务会并发跑回合

`scheduleCron` 的 tick 是 `void runTurnFromCron(...)`。回合比间隔长时，下一次 tick 会再开一个
→ 同一会话两个回合、消息交错、token 双倍消耗、界面两条回复同时在转。

**修法**：新增 `activeTurns`（`engine.isTurnActive(sessionId)`）。tick 撞上未结束的回合就
**跳过本次并广播 notice 说明**（`[定时任务] 上一次「…」还在执行，本次跳过…`）——
静默跳过会让人以为定时任务没生效，是最难排查的那种。

## 本轮修的第三个问题：engine.test.mjs 有 1/3 概率偶发失败

**这是接手时最先撞到的**：`ℹ pass 14 / fail 1`，失败的是「Agent 工具把内部调用标记为

### 档位选择（关键决策，别以后又调回去）

817 个报错里 379 个是 TS7006「参数隐式 any」——全是没写 JSDoc，**不是 bug**。
全补完不现实，且会把有价值的报错淹没。所以：

- 关 `noImplicitAny` → 817 → 94
- 关 `useUnknownInCatchVariables`（JS 里 catch 到的是 `{}`，`err?.message` 一律报错）→ 94 → 52

**验证过这套配置有牙齿**：拿两类真 bug 模式探过，都能抓到 ——
① 对象字面量写了类型里没有的属性（TS2353，正是 hooks.mjs `hookInput` 那类）；
② 可能为空却直接取值（TS18047，正是 `ws.OPEN` 那类）。

### 三类「类型契约与实际不符」（比没有类型更糟）

1. **`hooks.mjs` runEventHooks**：签名是 `({toolName='', hookInput, cwd=...} = {})`，
   TS 从默认值 `= {}` 推断出 `{toolName?, cwd?}`，**`hookInput` 整个漏掉** →
   engine / index 共 6 个调用点报 TS2353，而运行时一直是好的。补 `@param` 后消失。
2. **`deepseek.mjs` chatCompletion**：`content` 只写 `string`，但多模态传的是 content parts 数组；
   `onDelta` 标成必填而代码里本来就有空实现兜底。→ 抽 `WireMessage` typedef
   （content: string|null|数组；null 是 assistant 只发工具调用时的合法值）。
3. **`mcp.mjs`**：两种 transport 的 `send()` 返回类型不同，`kind` 没标字面量导致
   `t.kind === 'http'` 收不了窄。→ 定义判别联合 `Transport`。

### JS 里三个反复出现的推断坑（已在原地写注释）

- **空数组 → `never[]`**：hooks configCache / sessions blankSession / workflow run /
  WebSearch parsed。一处不标，后面几十条"属性不存在于 never"。
- **`.filter(Boolean)` 不做类型收窄**：paths 候选目录 / settings 权限桶 / WebSearch 结果。
- **初始值被推成字面量类型**：`result: null` 之后赋字符串报错；
  `let action = 'keep'` 与返回类型的 `'keep'|'remove'` 对不上。

### 顺带

- `deepseek.mjs`：`response.body` 为 null 时会抛看不懂的 "Cannot read properties of null"，
  现在明确报 `EMPTY_BODY`。
- `tools.mjs`：`degraded(...)(input)` 传了参数也不用（死代码），去掉。

差点是"只改类型却改了行为"。改完必须回头核对变量名指代的是不是同一样东西。

### 阶段 1a：web 不再用正则扫描 CLI 源码（`0144efc`）

`web/server/commands.mjs` 原先用正则扫 `commands/*.ts` 文本，靠"取缩进最浅的
`name:`"猜命令名。真出过事：`insights.ts` 里报告分节的 `name: 'project_areas'`
（缩进 4）盖过真正的命令名 `insights`（缩进 2，在 1600 行之后）。

改为 CLI 侧用 **TypeScript 编译器 API 解析 AST** 生成清单
（`scripts/gen-command-manifest.mjs` → `web/server/data/commands-manifest.json`），
web 直接读。AST 只取导出对象字面量的**直接属性**，嵌套字段天然不会被误取。

**解析器要认的 5 种形状**（逐个踩出来的，下次别重写）：
```
export default { ... }
export default () => ({ ... })        // 懒加载（login）
const cmd = { ... }; export default cmd
export const cmd = { ... }            // 命名导出（context 有俩同名导出，交互/非交互各一）
export default factory({ ... })       // 工厂函数（security-review）
```
外加 `as` / `satisfies` / 括号包装，以及工厂函数要穿透 CallExpression 取实参。

**顺带清掉 7 个空壳占位**（`@generated stub from scan-missing-imports`，fork 时
自动生成的 Proxy noop）。旧的"文件名兜底"把它们列成了 /torch、/force-snip、
/proactive，用户点了也没用。命令数 83 → 78。

**踩的坑**：哈希新鲜度校验两端算法必须完全一致 —— ① 目录只在真有 index.ts 时
计入；② 哈希输入用**相对 CLI 根**的路径，不是相对 commands/。否则每次启动都误报。

### 阶段 1b：钩子事件名与权限模式改为单向契约（`41af55a`）

web 原先硬编码 8 个支持事件 + **手抄 19 个"未支持"事件** + 权限模式名。
改为 CLI 侧 AST 提取生成 `cli-contract.json`，web 新增 `clicontract.mjs` 读。

两处实质改进：
1. 未支持事件改成 `全部 - 已支持` **算出来**（实测与原来手抄的 19 个完全一致）。
   以前 CLI 每加一个事件 web 就漏一个，且不报错。
2. 启动自检：web 声明的名字必须在契约里，否则告警。

契约读不到**直接抛错不降级** —— 它是判断"名字合法吗"的依据，读不到就闭眼放行
等于把用户配错的事件名当成"web 不支持"糊弄过去。
