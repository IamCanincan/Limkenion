# limkenion

Limkenion 命令行编程助手。纯文本交互界面，加上一个可以管道的非交互模式，
以及一个浏览器界面。

## 安装

```bash
npx limkenion web     # 不安装，直接用

npm install -g limkenion
export DEEPSEEK_API_KEY=sk-...
limkenion
```

## 用法

```bash
limkenion                               # 交互模式
limkenion "给这个仓库补一个 LICENSE"       # 执行一条指令后退出
limkenion -p "解释 src/config.ts"        # 显式写法
cat error.log | limkenion -p "分析这个报错"  # 从标准输入读取指令
limkenion -c                            # 继续当前目录下最近的会话
limkenion -m deepseek-v4-pro -v "重构这个模块"
```

| 选项 | 说明 |
|------|------|
| `-p, --print <文本>` | 一次性执行并输出结果 |
| `-m, --model <id>` | 指定模型，默认 `deepseek-flash` |
| `-c, --continue` | 继续当前目录下最近的会话 |
| `--api-key <key>` | 指定 API Key，默认读 `DEEPSEEK_API_KEY` |
| `--base-url <url>` | 指定接口地址 |
| `--max-turns <n>` | 单次指令最多几轮工具调用，默认 25 |
| `--retries <n>` | 限速或 5xx 时的重试次数，默认 2，`0` 表示不重试 |
| `--approval <mode>` | 工具审批：`auto` 常规操作直接放行（疑似危险命令仍要确认）、`ask` 读写前确认、`readonly` 只读，默认 `auto` |
| `-v, --verbose` | 显示思维链与完整工具输出 |
| `-h, --help` / `-V, --version` | 帮助与版本号 |

长会话会自动压缩上下文：先无成本地裁掉很久以前的大段工具输出，超过上下文窗口 75% 时再生成一次结构化摘要（CLI 会往 stderr 写一行「上下文压缩：…」）。

交互模式下 `/rewind` 可以回滚上一轮对文件的改动（改过的写回旧内容、新建的删除）：每轮开始前会把被改文件的旧内容记在会话文件旁边，所以长时间跑也随时能后悔。

子命令 `limkenion doctor` 用来排查「为什么跑不起来」：逐个检查 Node 版本、目录权限、密钥来源与存储方式、模型、接口可达性，给出结论与退出码（有 fail 为 1）。连不上时它会多说一层：列出实际生效的代理变量（口令打码）并说明 Node 自带的 fetch 默认**不读**它们、只有 `NODE_USE_ENV_PROXY=1`（Node 24 及以上）才作数；证书类失败指向 `NODE_EXTRA_CA_CERTS`，并提醒 **Node 的 fetch 不读 `SSL_CERT_FILE`**（curl / git 认它不代表这里认）。

内置工具八个：`bash`、`read`、`write`、`edit`、`grep`、`glob`、`todo_write`、`todo_read`；计划模式下
另挂一个 `exit_plan_mode` 用来提交方案（没有评审入口时不注册，模型会被要求把方案写成回答）。

改文件有一条硬约束（**读取证据**）：`edit` 与覆盖已存在文件的 `write` 要求先 `read` 过，且读过之后
内容没被改动，否则会被拒绝并提示重新读取——避免模型凭印象把改动盖上去；新建文件不受限制。

搜索用 `grep` 与 `glob`：跨平台行为一致，且自动跳过 `.git`、`node_modules` 等目录，遍历文件数、
单文件体积与结果条数都有上限，搜索范围被夹在工作目录内。

交互模式下的命令：`/help`、`/quit`、`/clear`、`/model <id>`、`/history`、`/rewind`、
`/plan [strict|guide|off]`、`/review`、`/style [名字]`、`/search <词>`、`/approvals [clear]`，
外加 `commands/` 目录里的自定义命令（见下）。
`Ctrl+C` 中断正在进行的回答，在提示符下再按一次退出。

## 浏览器界面

```bash
limkenion web                            # http://127.0.0.1:4887 并打开浏览器
limkenion web --no-open                  # 只起服务，不打开浏览器
limkenion web --port 0                   # 让系统分配空闲端口
limkenion web --host 0.0.0.0 --port 8080 # 对局域网开放，无认证，谨慎使用
```

启动时会尝试用系统默认浏览器打开地址。SSH 会话下不会打开——浏览器不在本机，
打开没有意义，此时只打印地址，端口转发交给 SSH 客户端或编辑器。

| 选项 | 说明 |
|------|------|
| `--port <n>` | 监听端口，默认 4887，`0` 表示由系统分配 |
| `--host <addr>` | 监听地址，默认 `127.0.0.1`，可选 `::1`、`localhost`、`0.0.0.0` |
| `--no-open` | 不打开浏览器 |
| `-m, --model <id>` | 新建会话使用的模型 |
| `--api-key` / `--base-url` | 同上面的全局选项 |

界面能力：

- **会话列表与切换**：读同一份 JSONL 会话存储，可新建、切换、删除。正在生成的会话带状态点。
- **流式对话**：正文增量渲染 Markdown（代码块、列表、标题、行内格式），思维链折叠展示。
- **工具审批**：`ask` 模式下，write / edit / bash 执行前在对话流里弹确认卡片（工具名、原因、
  参数、拒绝 / 允许 / 本会话总是允许）；写到工作目录之外在任何模式下都要确认。卡片上的
  「本会话总是允许」只在审批层给出了可记前缀时出现——`npm test` 这样的命令按「命令 + 子命令」
  记，write / edit 按所在目录记，并在按钮上写明它到底放行了什么。越界写入与疑似危险命令**没有**
  这个按钮：它们每次都该单独判断（内存里那张表进程退出即失效，不落盘）。
- **用量与缓存命中**：输入框那行的状态药丸显示最近一轮的 `↑输入 ↓输出 · 上下文占用 · 缓存命中率`，
  悬停给出本会话累计（轮数、输入、输出、命中数与命中率），切会话归零。**不显示金额**——那不是账单，
  是一份会过期的估算（价格表要人工跟着官方页改、分时还按时区判断）。占用比例取的是**最后一次请求**
  实际发出去的 token，不是本轮累计（一轮里跑 5 次模型，累计会是窗口的好几倍）。
- **工具行**：一次调用一行——符号、工具名、等宽摘要（bash 显示命令、文件工具显示路径）、状态与耗时；
  点这一行（或回车/空格）展开参数与输出，失败自动展开。带 `path` 的工具在展开后有「预览文件」入口。
- **运行提示与重试**：上下文压缩、超窗救援、这一轮失败都会记在对话末尾的提示区（最多 20 条），
  **刷新页面也还在**（以前失败只在事件流里一闪，紧接着的整体重绘就把它抹掉了）。可重试的失败旁边
  有「↺ 重试」按钮，走 `POST /api/sessions/:id/retry`，它重发的是**当前这一轮**而不是把输入框里的
  文字再发一遍——失败时用户消息已经进了历史，重新 prompt 会多出一条重复指令。
- **运行提示分两处**：「上下文压缩 / 超窗救援」这类背景状态贴着输入框显示（不占对话正文）；某轮失败与
  「↺ 重试」留在对话末尾，刷新与断线重连后仍在。
- **两侧都能开合、也都能拖宽**：顶栏最左「▾ 侧栏」收放会话列表（默认展开），最右「▤ 面板」开关右侧面板；
  左栏拖右边缘（200–520px）、右栏拖左边缘（280–640px），双击复位，键盘 ←/→ 也能调，窄屏自动隐藏拖柄。
- **切会话不打断任何一边**：点开另一个会话只是换看哪一条对话——旧会话那一轮在服务端照旧跑完（切回去时快照把进度
  带回来），终端面板那条命令照旧跑；**输入框里的草稿与文件面板里未保存的改动按会话各留一份**，切回来原样还在
  （也不会串到别的会话里）。历史面板跟着你选的会话重新列一遍。文件面板那一格是「工作区浏览器」，跟着**当前
  工作目录**走，切会话不动它。
- **会话列表是平铺的（跨工作目录），可以拖着排序**：一条条排，不是当前工作目录的会话会在行内标出它属于
  哪个工作区。**按住一行往上/下拖**就能改次序（落点画一条强调色细线；键盘是 `Alt+↑` / `Alt+↓`），
  次序写进会话文件头的 `order` 字段（`POST /api/sessions/order`，一次给整份列表重排）——所以它是**内容**
  而不是界面偏好，换台机器打开同一个配置目录也还在。规则只有一条：**拖过的按你排的，没拖过的按最近使用**，
  因此刚建的会话仍然落在最上面；排过序之后的会话再被写入消息也不会自己跳位。正在生成的会话不会被重排
  （重写文件头与追加消息会撞车），界面上会说明有几个没动。点开一个别的工作区的会话**不再先切全局工作目录**
  ——会话在哪个目录里干活取自它会话头，服务端按 id 跨目录找得到它。
- **顶上是「新建会话」，工作目录在会话行的 `▾` 菜单里选**：**默认没有工作目录**——`limkenion web` 不再拿
  启动目录兜底，第一次用要先选一个（没选时点「新建会话」或在输入框里发送都会被挡下来并直接打开选择器，
  服务端那边也会 409）。选目录只有两个入口：顶上的「新建会话」（一个会话都没有时它先把选择器摆出来，
  新建的会话就落在选中的目录里）和会话行 `▾` 菜单里的「工作目录」（改的就是那一行的会话）。选择器可逐级
  进入子目录、退回上一级，也可以直接粘绝对路径，或就地新建文件夹。菜单里那条走的是「只给这个会话换目录」
  的路（`POST /api/cwd` 带 `session`）：服务端不重建运行注册表，别的会话哪怕正在生成也不受影响。
  **换完目录当前工作目录一起跟着走**：文件面板、终端、搜索、体检以及之后新建的会话看的都是它。
- **会话可重命名**：会话行的 `▾` 菜单里「重命名」就地弹一个输入框，回车保存、Esc 取消；留空等于取消命名，
  列表退回显示首条用户消息。名字存在会话文件的头里（不是一条记录），改名只重写第一行，消息一条不少。
- **顶部只有常用的四个入口**：`⌕ 搜索`（跨会话搜内容）、`▾ 计划`、`▾ 审批`（干活时最常切的两件，档位
  写在 chip 上）、`▤ 面板`。风格、压缩、已放行规则这些「设一次」的东西在面板的**「设置」标签**里，
  每件一块框：标题 + 它在决定什么 + 分段按钮 + 当前这档什么后果。
- **顶部模式条**：计划（关 / 严格 / 引导）、审批（自动 / 确认 / 只读）与输出风格（默认 / 简洁 / 解释）
  三个开关，都是会话级、点了立刻生效；输入框里打 `/` 会列出内置命令与 `commands/` 目录里的自定义命令
  （键盘上下选择、Enter 确认）。
- **右侧面板**：历史（逐轮差异与回滚）、文件（树 + 预览 + 编辑）、终端、评审（多角度代码评审）、
  诊断（与 `limkenion doctor` 同一批检查）。
- **模型切换、工作目录切换、停止生成**。换目录走会话行 `▾` 菜单里的「工作目录」→ 选择器：改的是
  **这个会话**的目录（服务端只改它、不重建注册表），同时把当前工作目录一起挪过去，文件面板与终端
  跟着换。**回滚在右侧面板的「历史」标签里**：逐轮列出这一轮改了哪些文件（带 diff），每轮段头一个
  「↺ 回滚到这一轮」——撤的是这一轮**以及它之后**的轮次，撤之前先看要撤掉什么。「清空上下文」让模型
  忘掉之前的对话
  （会话文件仍保留，与命令行的 `/clear` 一致；清空会往会话文件里写一条标记，所以**重开这个会话
  也不会把旧对话带回来**），「已放行 N 条」显示本会话点过「总是允许」的操作，点一下全部忘掉——
  命令行那边对应的是 `/approvals`。
- **计划模式的两档在网页上也走得通**：模型提交方案时弹评审卡片——方案全文加一个反馈框，
  「按方案执行」就离开计划模式开始动手，「退回修改」必须写一句反馈（没写时按钮是禁用的）。
  批准之后顶部的档位 chip 会跟着变成「关」，不会还写着「严格」。
- **接口密钥在网页上填**：点侧栏「接口密钥」粘贴保存即可，下一次生成立即生效，不必重启服务。
  密钥加密后落在本机 `auth.json`（Windows 用 DPAPI，只有本机本用户能解；其它平台退回明文 0600，
  界面会写明）；接口只回打码后的预览与来源，明文不出服务端，也不进会话记录。
- **用量与耗时**：状态那一行显示最近一轮的输入/输出 token、上下文占用百分比与耗时；代码块右上角
  有复制按钮。
- **多会话并行**：不同会话可以同时生成，各自独立推流。
- **文件只读预览**：右侧栏，超长截断，二进制文件提示不支持。
- **主题**：只跟随系统的深浅色（`prefers-color-scheme`），系统一切换就跟着变，不提供手动
  切换——颜色全由 CSS 变量决定，页面不存任何选择。主题色是粉色。
- **外观按 Material Design 3 Expressive 做**：顶栏、侧栏、面板、输入框、浮层都是半透明玻璃面
  （`backdrop-filter` 三档：12 / 20 / 30px + 提饱和），圆角 12–32px，浅色主题铺一层柔和色晕让玻璃
  有东西可糊；深色主题页面保持纯黑。字体随包提供 Google Sans Flex。

### 实现方式

前端是手写的 HTML/CSS/原生 JS，**没有构建步骤、没有前端依赖**，由服务器直接托管。
服务端也只用 `node:http`：

- 静态资源：`GET /` 与 `public/` 下的扁平文件名（`index.html`、`app.css`、各 ES module、
  `google-sans-flex.woff2` 字体），源码在 `src/web/public/`，构建时复制到 `dist/web/public/`。
  白名单用正则限定，不含 `/`，因此请求路径无法穿越出该目录。前端拆成 11 个模块，导入图无环。
- 字体：Google Sans Flex，Google 开源（SIL OFL 1.1），文件随包提供，**不请求外部 CDN**，
  离线可用；许可证原文见 `src/web/public/google-sans-flex-LICENSE.txt`。它只有拉丁字形，
  中文由系统字体接手。
- JSON API：`/api/state`、`/api/sessions`、`/api/file`、`/api/model`、`GET /api/dirs`（列出子目录）、
  `POST /api/dirs`（新建文件夹，只建一层并校验名称）、`POST /api/cwd`（切换工作目录：不带 `session` 时
  换全局目录并重建运行注册表；带上 `session` 时只给那一个会话换文件与运行、别的会话不受影响，但当前
  工作目录会一起挪过去，所以面板与终端也跟着换，**不重建注册表**）、
  `GET/POST/DELETE /api/credentials`（读密钥状态、保存、清除；明文永不回页面）。
- 流式输出：`GET /api/sessions/:id/events` 是 SSE。`history` 与 `pending` 是**状态快照**，
  客户端收到就整体重绘，因此断线重连不会出现增量错位；另有 20 秒注释行心跳保活。
- 输入：`POST /api/sessions/:id/prompt`（`202` 立即返回，生成过程走 SSE）、`POST .../abort`。

### 安全姿态

默认只绑定 `127.0.0.1`，没有 TLS、没有认证，与 dsh 的 web 宿主一致。因此额外校验：

- `Host` 头必须是回环名字（`127.0.0.1`、`::1`、`localhost`）。这挡掉 DNS rebinding：
  恶意域名解析到 127.0.0.1 时浏览器发来的 `Host` 是攻击者域名，会被拒绝。
- 带 `Origin` 的请求必须与服务端自己的 `Host` 一致，挡掉跨站请求。`curl` 之类没有
  `Origin` 的客户端不受影响。
- 密钥只经 `POST /api/credentials` 单向写入本机 `auth.json`（0600），读接口只回打码预览与
  来源，明文既不出服务端也不进会话记录；会话文件里同理只有对话内容。

`--host 0.0.0.0` 是明确的对外暴露，此时不再做 Host 校验，只应部署在可信网络。

## 输出约定

模型正文走 **stdout**，思维链、工具活动、状态与错误走 **stderr**。
因此 `limkenion -p "..." > answer.txt` 得到的是干净的答案，可以直接管道给别的程序。

退出码：**0** 正常结束，**1** 运行失败（接口报错、响应流被提前掐断、超过最大轮数），**2** 用法错误，
**130** 用户中断。注意「工具执行失败」不算运行失败——模型拿到了失败结果并继续作答，那一轮是完整的；
只有这一轮根本没答成才会是 1，所以 `limkenion -p "..." || echo 失败` 这样的写法是可靠的。

## 配置与凭据

密钥不用每次设环境变量，存一次就行：

```bash
limkenion auth login          # 交互式输入，不回显
limkenion auth login --api-key sk-...   # 适合脚本
limkenion auth status         # 看当前生效的是哪一把、来自哪里
limkenion auth logout         # 删除本地保存的密钥
```

跑 `limkenion web` 时可以完全跳过命令行：在网页侧栏点「接口密钥」粘贴保存，下一次生成就用它，
不用重启服务。两种入口写的是同一个文件。

密钥保存在 `<配置目录>/auth.json`，文件权限 `0600`，与普通配置分开存放，
这样备份或分享配置时不会连密钥一起带出去。

生效优先级：`--api-key` 参数 > 环境变量 `DEEPSEEK_API_KEY` > 本地保存的密钥。
`auth status` 会把三者都列出来，密钥一律打码显示。

普通配置放在 `<配置目录>/config.json`：

```json
{
  "model": "deepseek-v4-pro",
  "baseUrl": "https://api.deepseek.com",
  "maxTurns": 40,
  "verbose": true
}
```

| 键 | 说明 |
|----|------|
| `model` | 默认模型 |
| `baseUrl` | 接口地址 |
| `maxTurns` | 单次指令最多几轮工具调用 |
| `retries` | 限速或 5xx 时的重试次数，0-10 |
| `approval` | 工具审批模式：`auto` / `ask` / `readonly` |
| `compaction` | 上下文压缩：`auto`（默认）或 `off`；占用用上一轮真实用量校准 |
| `planMode` | 默认计划模式档位：`off`（默认）/ `strict` / `guide` |
| `style` | 输出风格：`default`（默认）/ `concise` / `explanatory` |
| `hooks` | 工具钩子，见下 |
| `verbose` | 是否默认显示思维链与完整工具输出 |

优先级同样是命令行 > 环境变量 > 配置文件。

### 配置分三层

配置文件按优先级从低到高叠三层，逐键覆盖；命令行与环境变量再盖在最终结果之上：

| 层 | 位置 | 范围 |
|----|------|------|
| 项目 | `<工作目录>/.limkenion/config.json` | 只认**安全子集**：`maxTurns`、`compaction`、`verbose`、`planMode`、`style`、`approval` |
| 用户 | `<配置目录>/config.json` | 全部键 |
| managed | Windows `%ProgramData%\limkenion\managed-settings.json`，其它系统 `/etc/limkenion/managed-settings.json`（`LIMKENION_MANAGED_SETTINGS` 可覆盖） | 全部键，通常是机器上统一发的策略 |

项目层是一道**安全边界**，不是风格偏好：项目配置跟着仓库走，clone 一个陌生仓库就等于让它的作者
替你写配置。所以 `baseUrl`（会把密钥送去别人的服务器）、密钥、`hooks`（等于远程执行代码）与
`model` 在项目层一律不认——只留下「在这个仓库里怎么干活」这类键。被忽略的键不会静默消失，
`limkenion doctor` 会把每层生效了哪些、忽略了哪些连同原因一起打出来。

### 工具钩子

`hooks.preToolUse` 让你在工具真正执行前插一道自己的检查。每条钩子是一个 `matcher`
（工具名，支持 `*` 和逗号分隔，如 `write,edit`）加一条 `command`：

```json
{
  "hooks": {
    "preToolUse": [
      { "matcher": "bash", "command": "node scripts/guard-bash.mjs" },
      { "matcher": "write,edit", "command": "node scripts/check-paths.mjs" }
    ]
  }
}
```

命令从标准输入拿到这次调用的 JSON，再用标准输出回答：

```
输入：{ "tool": "bash", "input": { "command": "rm -rf build" }, "cwd": "/path/to/project" }
输出：{ "decision": "allow" | "deny" | "modify", "reason": "给模型看的一句话", "input": { ... } }
```

退出码沿用一套固定约定，为的是「钩子自己坏了」不会把 agent 卡死：

| 退出码 | 含义 |
|--------|------|
| `0` | 读标准输出的 JSON，缺字段按放行处理 |
| `2` | 拒绝这次调用，标准错误作为理由回给模型 |
| 其它非 0 | **放行**，标准错误作为警告附在工具结果后面 |
| 超时（10 秒）或输出不是合法 JSON | 同上，放行加警告 |

顺序是：内置的审批与计划模式先判定，钩子只在放行之后才有机会说话——所以钩子翻不掉
计划模式的拒绝。`modify` 会更新入参并继续交给下一条钩子，每条钩子看到的都是当前入参。
`LIMKENION_HOOK=pre-tool-use` 会写进环境变量，方便脚本复用。

钩子是你自己写的代码，以你的权限运行，也会正常影响 agent 的行为，动手前先想清楚。

## 计划模式

先出方案、批准后再动手。两档的区别只在**靠什么约束**：

| 档位 | 约束方式 | 适合 |
|------|----------|------|
| `strict` | 工具层强制：只放行 `read` / `grep` / `glob`，`write` / `edit` / `bash` 一律拒绝 | 没批准之前一个字节都不许动 |
| `guide` | 提示词引导（DSH 的做法）：工具不设限，但要求先探索、先出方案 | 想让模型少撞墙，安全性交给审批模式与沙箱 |

进入方式三种，优先级命令行 > 配置文件 > 默认关闭：

```bash
limkenion --plan                        # 严格档启动；也可以 --plan guide
limkenion -p "重构这个模块" --plan guide  # 一次性执行也能带档位
```

```json
{ "planMode": "strict" }
```

交互模式里用 `/plan` 随时切换：不带参数是「关着就进严格档、开着就退出」，也可以 `/plan guide`、
`/plan off`。

不管哪一档，模型都通过调用 `exit_plan_mode` 交方案：终端会把方案原文打出来，回车或 `y` 批准
（随后离开计划模式、按方案执行），`n` 或直接输入一段话则把方案连同反馈退回去重写。非交互运行
没有评审入口，这个工具会明确要求模型把方案写成回答——批准永远需要一个能回答的人。

## 代码评审

对当前改动跑一轮多角度评审，专门用来在提交前找问题：

```bash
limkenion review                  # 工作区相对 HEAD 的改动（含已暂存）
limkenion review --base main      # 评审 main...HEAD，适合看一个分支改了什么
limkenion review --focus security # 只跑指定角度，逗号分隔
```

交互模式里也有 `/review`。

**为什么是几个 agent**：一个上下文里同时想「找缺陷」「看安全」「看测试」，注意力会互相稀释——
先发现的问题会主导后面的判断。所以三个互不通气的评审者各跑一遍，再由一个汇总者去重、砍掉没有
证据的条目、按严重级别排序。评审者只拿 `read` / `grep` / `glob` 三个工具并以只读模式运行，它们
看代码但改不了任何东西。

**规矩写死在提示词里**：每条问题必须给出 `文件:行号`、为什么是问题、什么条件下触发；没把握的
放进「待确认」；纯风格偏好不许报；最多 8 条。汇总者只做合并与排序，不许引入新问题。

报告走 stdout，进度走 stderr，所以可以直接重定向：

```bash
limkenion review --focus correctness > review.md
```

退出码：**0** 没有 blocker，**1** 存在 blocker（CI 里直接当门禁用），**2** 评审没能跑起来
（没有密钥、不是 git 仓库、工作区没有改动、所有评审者都失败）。汇总结果里必须出现 `VERDICT: block`
或 `VERDICT: ok` 这一行，缺失时按「没有 blocker」处理并在 stderr 里说明。

## 输出风格

同一个 agent，赶时间时只想看结论，学新东西时想听清为什么。风格是**怎么讲**，不改变**怎么做**：
工具、审批、计划模式一概不动。

| 风格 | 行为 |
|------|------|
| `default` | 正常说明改了什么、验证了什么（不加任何额外要求） |
| `concise` | 先给结论；不复述工具输出、不预告下一步、不解释显而易见的过程 |
| `explanatory` | 说清为什么这么做：关键取舍、被否决的做法、影响到的其他地方 |

三处入口，优先级命令行 > 配置文件：

```bash
limkenion --style concise "顺一下这个模块的错误处理"
```

```json
{ "style": "explanatory" }
```

交互模式里用 `/style` 看当前风格、`/style concise` 切换。项目配置也可以设 `style`——它是团队
约定，没有安全影响，所以留在项目层的安全子集里。

## 自定义命令

一个命令就是一个 Markdown 文件，放在 `<配置目录>/commands/`（Windows 是
`%APPDATA%\limkenion\agent\commands`）：文件名即命令名，正文即提示词，正文里的 `$ARGUMENTS`
会被命令后面跟的文本替换，没有占位符时参数附在末尾。

```markdown
---
description: 按仓库约定提交改动
argument-hint: [范围]
---

看一下 `git diff $ARGUMENTS`，按仓库的提交约定分条写好提交信息并提交。
```

元数据是可选的，只有文件**第一个非空行恰好是 `---`** 时才开始解析，遇到下一行 `---` 结束。
只认三个键：`description`（`/help` 里的一行说明，不写就退回正文首个非空行）、`argument-hint`
（跟在命令名后面的参数提示）、`when-to-use`（更长的使用场景，暂不显示）。键名不区分大小写、
`-` 与 `_` 等价，值两端成对的引号会去掉，块里的空行、`#` 注释与不认识的键都忽略。整块元数据
**不会**发给模型；块没闭合或已知键写空时命令照常可用，只在 `/help` 里多一行提示。

交互模式里 `/<命令名> [参数]` 即可调用；扩展成本就是「放个文件」，不用改源码。

## 项目说明

工作目录及其上级目录里的 `AGENTS.md` 会被自动注入系统提示词，不需要在对话里重复交代
项目约定。发现规则：

1. 全局先看 `<配置目录>/AGENTS.md`，第一个存在的胜出。
2. 项目侧从工作目录向上找，按 `AGENTS.override.md` → `AGENTS.md` → `CONTEXT.md` 的顺序尝试，
   **第一个有命中的文件名胜出**，后面的名字直接不看。所以同时存在 `AGENTS.md` 和
   `CONTEXT.md` 时只读前者。
3. 胜出的那个名字，沿路径向上的**所有**命中都会注入。子目录里的 `AGENTS.md` 因此可以
   覆盖仓库根的说明，注入顺序是由近到远。

上限是单文件 32KB、合计 64KB，超出会截断并标注。向上查找不会越过 git 仓库根。

提示词里还会带一段环境信息（工作目录、是否 git 仓库、平台、今天日期）——模型不知道
今天是几号，缺了它会把「最近」「当前版本」这类判断做错。

每轮提问前都会重新读一遍，所以改完 `AGENTS.md` 直接接着问就生效，不用重启；
文件没变时不会改动系统消息，以免白费服务端的前缀缓存。

## 会话

会话按工作目录分开存放：`<会话目录>/--<编码后的工作目录>--/<时间戳>.jsonl`。
第一行是会话头，之后每行一条消息。文件是可读的 JSONL，可以直接用 `grep`、`jq` 查看。

- 交互模式每次启动都会新建一个会话文件。
- `limkenion -p` 默认不写会话文件，避免零散提问混进会话列表；加 `--continue` 才会续写。

### 搜索历史会话

JSONL 本来就能 grep，做成命令是为了补上 grep 做不到的事：跳过逐轮快照文件（它们同目录同后缀，
混进来会把回滚记录当成对话）、把命中还原成「哪个会话、第几条、谁说的」、以及只给一行片段。

```bash
limkenion search "RepeatGuard" --limit 10
```

交互模式里是 `/search <关键词>`。大小写不敏感的子串匹配——用户随手输的内容里全是正则元字符，
而搜索这件事「搜不到」比「搜得不够花」更让人困惑。用法像 grep：**有命中退出 0，没有命中退出 1**，
所以可以直接写进脚本。命中会带上会话文件与行号，用 `read` 打开那个文件就能看完整上下文。

## 改自己（self）

这个 agent 可以改自己的源码，`self` 负责把改动**安全地换上**：

```bash
limkenion self update --from <源码目录>   # 门禁 → 打包 → 存产物 → 交给独立进程安装
limkenion self update --dry-run           # 只做到打包，不安装
limkenion self rollback                   # 装回上一版
limkenion self status                     # 当前版 / 上一版 / 上次结果 / 日志位置
```

两条不可调换的约束，都是为了「换不坏」：

1. **门禁不过就不装**：先跑完整 `npm run check`（biome + 依赖/许可/导入检查 + `tsgo`）与三个套件，
   失败立刻停在原地，当前装着的版本一个字都不动。让没过测试的版本顶掉能用的版本，是自更新最糟的
   失败方式。
2. **不在运行中的进程里覆盖自己**：Windows 上正被加载的文件无法替换，`npm install -g` 会失败或留下
   半套文件。所以安装交给一个**分离的子进程**——它等本进程退出后才动手，装完校验版本号，失败就用
   上一版装回去，结果写进 `<配置目录>/versions/install.log`。安装脚本本身也放在那里
   （`install.cjs`），出问题可以直接看。

每次安装过的 tgz 都存在 `<配置目录>/versions/` 下，`state.json` 记住当前与上一版，所以回滚只是
「拿上一版再跑一次同样的安装」。

**兼容性由测试守住**：`packages/core/test/compat.test.ts` 与 `packages/cli/test/compat.test.ts`
钉住导出面（删一个导出会变成编译错误）、退出码、以及会话/快照文件对未知字段与半行的容忍度；
`AGENTS.md` 里那份「修改自己时的规矩」是给人的，这两份契约是给 CI 的。

## 设计取舍

- **权限只有审批，没有沙箱**：`--approval readonly` 能挡住写入与命令、工作目录之外的写入默认要
  确认，但审批通过后工具仍以当前用户权限直接执行。需要真正隔离就用容器或沙箱运行。
  审批里另有一层保守的**危险命令启发式**（`rm -rf`、`git reset --hard`、`git clean -f`、
  `chmod -R 777`、`dd of=/dev/…`、`curl … | sh`、叉子炸弹等，会先剥掉 `sudo` / `env` / `bash -lc`
  这类外壳再看内层）：它只把判定往严的方向抬，`auto` 档也照样会问一句。它在 token 层做近似解析，
  动态拼出来的命令一定骗得过它——所以它是保险，不是沙箱。无人可问时（管道、CI、`-p`）这类命令按
  拒绝处理，并把「需要确认但当前不是交互终端」写进 stderr。
- **没有 TUI**：不引入差分渲染与键盘绑定，代价是界面朴素，收益是没有终端兼容性负担。
- **没有扩展机制**：需要新工具就实现 `AgentTool`，用 `limkenion-core` 自己组装。
- **只支持 DeepSeek**：只要兼容 OpenAI 的 `/chat/completions`，改 `--base-url` 也能接其它服务。
