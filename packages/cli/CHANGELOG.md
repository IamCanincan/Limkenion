## [1.0.0] - 2026-09-15

### Changed

- **不再读 `CLAUDE.md`**：项目说明文件的候选只剩 `AGENTS.override.md` → `AGENTS.md` → `CONTEXT.md`
  （`--help` 里那行也照改），全局层只认 `<配置目录>/AGENTS.md`。原来就写着 `CLAUDE.md` 的仓库
  把它改名成 `AGENTS.md` 即可，内容不用动。
- 注释与文档里不再提及其他工具或项目的名字：设计取舍照旧写明（「为什么这么定、踩过什么」），
  但不写成「某工具是这么做的」；README 里那段来源致谢与发布说明模板里的对应段落一并去掉，
  许可证要求的版权声明仍完整保留在 `LICENSE`（随每个包分发）。
- **`self update` 的序列抽成 `runSelfUpdate()`**：门禁 → 打包 → 记下旧版 → 交给分离进程这一段
  终端与网页共用（网页要的是「异步 + 有进度」，所以它通过 `onStep` / `onLine` 把进度交出去，
  不自己打印）。行为不变，`--dry-run` 仍是「做到打包为止」——它在共用之后差点变成「顺手也装了」，
  所以现在由 `runSelfUpdate` 的 `dryRun` 明确跳过挂作业那一步，并有测试钉住。
- 逐行回报构建输出时，执行器改用 `decodeProcessOutput` 按行切（不能按块 `toString("utf-8")`：
  Windows 上中文系统的控制台代码页会把它解成替换字符）。

### Added

- **网页上也能「更新」了**（不只是回滚）：先用 `limkenion web --from <源码目录>` 启动（新参数），
  设置面板那张卡片上就多一个「更新到源码当前状态」按钮，走新增的 `POST /api/self/update`。
  与回滚的**区别在代价**：更新要在源码目录里跑门禁与打包（几分钟），所以它是**异步**的——
  请求立刻回 202（一次只跑一个，重复点回 409），进度由卡片每两秒轮询 `GET /api/version` 拿，
  显示「正在跑门禁 / 正在构建并打包」以及构建输出的最后一行；跑完同样只把作业挂上，
  要停掉这个服务才真正安装。没给 `--from` 就不显示这个按钮（并说清为什么），更新照旧可以在终端跑。
  源码目录**只从启动参数来、不从请求体来**：否则一个 POST 就能让服务在任意目录里跑构建脚本。
  `web` 启动时会打印一行「自更新源码目录」或「网页上只提供回滚」。
- **`limkenion self versions [--prune]`：清理历史安装包**。自更新会在
  `<配置目录>/versions/` 下留 tgz，旧流程还会留整份 `installed-before-*` 备份目录——这台机器上曾经
  攒到 **69 个 tgz（53.7MB）+ 59 个备份目录（184.9MB）**。`self versions` 逐个列出来（大小、
  路径、★ 标出「在用的那一版与回滚点」），`--prune` 才真删：**只留 ★ 与最新一份备份**，
  目录里的其它文件（state.json、安装脚本、日志）一律不动。回收目录那一套同理——不自动清理，
  免得又变成静默删除。
- **终端工具行改用工具自陈的摘要**（与网页同一套口径）：`> bash echo hi`、`> write src/a.ts（3 行）`。
  从前终端把入参整坨压成一行 JSON 打出来（`> bash {"command":"echo hi"}`），与网页显示的完全不是一回事
  ——同一条工具调用在两个载体上长得不一样。取不到（老事件、历史里删掉的工具）仍退回压平的 JSON。
- **网页上可以**安排**回滚了**：设置面板那张卡片多了「回滚到上一版」按钮（没有回滚点时不给按钮），
  走新增的 `POST /api/self/rollback`。
  **它是「安排」而不是「执行」**：服务端把安装作业挂到分离进程上，那个进程等这个服务退出才
  `npm install -g`（Windows 上正在被加载的文件换不掉），所以回执写的是「请停止这个服务…装好再重新启动」，
  而不是「已完成」——说成已完成，用户会以为重启一下就好，实际什么都没装。服务端**不主动杀自己**：
  服务一停页面上什么都看不见，用户也不明白为什么。
  **更新**见上面那条（同样只从网页上「安排」，只是要先跑门禁与打包）。
- **`limkenion web --from <源码目录>`**：给网页上那个「更新」按钮指定源码目录；不给就只有回滚。
  新参数，缺省行为与从前一致（网页上不提供更新）。
- **`sessions trash [--empty]`**：`sessions rm` 把会话移到回收目录之后，原来没有查看与清空的入口
  （只能自己翻文件系统）。现在 `trash` 列出回收目录里有什么（时间、大小、路径），
  `trash --empty` 才是真删；`--all` 扫所有工作目录的回收目录。
  回收目录**不自动过期**——自动清理就是静默删除，与 `Session.remove()` 的注释同一条理由。
- **终端会话管理：`limkenion sessions`**。网页侧栏一直能看列表、改名、删除，终端这边只有 `-c` 续写
  与 `search` 找内容——想清理旧会话、或者给一个会话起个名字让 `search` 认得出来，都无从下手。
  现在：
  - `sessions` 列出**当前目录**下的会话（最近的在前，带条数、相对时间、名字或首条消息）；
  - `sessions --all` 跨工作目录（与网页侧栏、跨会话搜索同一份枚举），每行下面缀上它属于哪个目录；
  - `sessions rename <id> <名字>` 起名（名字给空串表示取消命名，界面退回显示首条消息）；
  - `sessions rm <id>` 删除——走 `Session.remove()`，**移到 `<会话目录>/.trash/` 而不是硬删**：
    会话是这个工具里唯一不可再生的东西，而命令行一个 `rm` 只差一次误敲。
  `<id>` 是列表里那一列前 8 位（uuid），也可以写 `latest`。REPL 里另有 `/rename [名字]` 给**当前**
  这个会话起名（`/rename -` 取消命名）——子命令要 id，而「我正在这个会话里」不需要查。
- **网页「设置」面板多了「版本与自更新」卡片**（新端点 `GET /api/version`）：终端一直能
  `limkenion self status` 看自己装的是哪一版、上一版能不能回滚、上次更新成没成，网页原来看不到。
  卡片给四行（当前版本 / 上一版可回滚 / 上次自更新 / 安装日志）与一句说明。
  **只读**：更新与回滚要替换正在运行的那个进程（Windows 上正被加载的文件换不掉），只能在终端里跑，
  所以卡片上写的是「在终端里跑 `self update` / `self rollback`」，而不是一个按下去只会失败的按钮。
  数据与 `self status` 共用 `readSelfStatus()`，两边不会各拼一份字符串。
- **终端 `/diff [轮次]`：先看再撤**。网页的「历史」面板一直是「逐轮 diff + 每段头上的回滚按钮」，
  终端却只有闭着眼睛的 `/rewind`。现在 `/diff` 打出那一轮改了哪些文件（`▸ 路径 +N −M`）、
  `@@` 段头与 `−`/`+` 行，末尾提示「撤掉这一轮及其之后共几轮：`/rewind <n>`」——
  回滚只能从最近一轮往回撤，所以提示给的是**能照着敲的那个轮数**。
  `/rewind` 也跟着能带轮数（`/rewind 2`），与 `limkenion rewind <n>` 同一套语义。
- **终端 `/approval [档位]` 与 `/compact [on|off]`**：这两个开关从前只能启动时用 `--approval` /
  `--no-compact` 定，干到一半想改只能退出重开（网页顶栏一直有 chip 可切）。两条都带**后果说明**
  （「只放行只读操作：read / grep / glob 与只读命令，其余一律拒绝」），不带参数只报当前档位。
- 一轮结束时打一行用量并补上**上下文占用**：`[3 轮，用量 1200 输入 / 340 输出，上下文 4.2 万/100 万（4%）]`。
  占用用的是 `contextTokens`（最后一次请求实际发出去的 prompt token）比**当前模型**的窗口——
  拿 `usage.promptTokens`（一轮里几次请求之和）去比会算出好几倍；`/model` 换过模型也按新窗口算。
  从前这一行只在 `-v` 下打且只有用量，现在每轮都打（网页那颗常驻药丸的等价物）。
- **终端也有了子代理工具**（此前根本没有）：`createSystemTools` 只在收到 `subagents` 时才注册那四个工具，
  而命令行的装配没传它——于是「把一批文件看完再总结」这类活只能让主对话硬扛，网页却能委派。
  现在两边共用 `createRunRuntime`（`web/run-agent.ts` 挪到 `src/run-agent.ts`，命令行走
  `createCliRuntime`），同一份能力不会再因为载体不同少一块。新增测试钉住「两边工具集一样全」。
- **终端新增三条命令**：
  - `/jobs`：列后台任务，`/jobs log <id>` 看输出尾部，`/jobs kill <id>` 停掉；
  - `/subagents`：看子代理进度，`/subagents stop` 全部停下（它们是独立的模型循环，会一直烧 token）；
  - `/todos`：看待办与目标。
  这三样以前终端里只有模型看得到（它们本来就是工具），用户既看不见也停不掉。
- 待办与目标**每轮结束时变了就打一遍**（与网页输入框上方那两行 dock 是同一件事）。
  只在变了的时候打：模型每轮都可能重写同一份清单，每轮都刷会把刚看的东西顶跑。

### Changed

- **`web/diff.ts` 挪到 `src/diff.ts`**，并把「一轮快照 → 各文件差异」也搬进去（`diffTurn`）：
  网页的「历史」面板与终端的 `/diff` 现在真的是同一份代码，`feature-history.ts` 只剩路由与响应拼装
  （196 行）。它不再属于 `web/`——终端也在用它，所以文件头那句「两个地方用它」改成了三个。
- **装配只有一处**：`createRunRuntime()` 从 `web/run-agent.ts` 挪到 `src/run-agent.ts`，
  命令行（`createCliRuntime`）与浏览器界面共用；`ReplOptions` 多 `jobs` / `subagents` / `todos` / `goals`
  四项，斜杠命令那八个位置参数收成一个上下文对象（加一样能力不必再动全部调用点）。
  历史加载也跟着搬进工厂（`session.load()`），网页的 `Run` 不再自己接一遍。
- 一次性模式（`-p`，默认不落盘）同样走这份装配：因此它也有子代理工具；但它没有逐轮快照
  （没有会话文件就没有快照），`/rewind` 那类能力自动缺席。

### Fixed

- **测试：web-server 那一组的偶发 `fetch failed`**。这一组反复起停服务、每个都用系统分配的临时端口，
  而端口很快被复用；Node 的 `fetch`（undici）按 origin 缓存 keep-alive 连接，上一个服务关掉后池里那条
  死连接还在，复用它的请求就报 `TypeError: fetch failed`。表现是**偶发**：单跑这个文件必过，
  全套件并行跑时红过两次（分别落在不同用例上）。现在该文件的请求带一次**只在连接层**失败时的重试
  （HTTP 状态码照原样走，不掩盖真失败）。顺带补上此前完全没有覆盖的「历史」端点路由测试
  （列表不给内容、单轮给编好行号的段、指定文件只算那一个、没改过的文件回 404）。
- **子代理不继承父的档位（安全口子）**：子代理从前一律按 `auto` 起，于是「ask 档下动手前要问一句」
  对它不成立——**一次委派就能绕过审批**去改文件，计划模式（严格）同理。现在它读的是父 agent
  **当下**的审批档位、计划模式、输出风格与钩子（运行期改过也跟得上）。子代理不弹确认卡片，
  所以继承 `ask` 之后它在没有确认入口时按**拒绝**处理——只能只读地干活，这正是要的 fail-closed。
  两条测试钉住：直接以 `ask` 起，以及 `auto` 建好之后运行期切成 `ask`。

- **待办与目标改由服务端按「会话事实」下发**：新增 SSE 事件 `facts`（`{ todos, goal }`），并进连接快照
  （刷新页面、断线重连、换标签页都能看到同一份）。它取自**工具层正在用的那两份状态**（内核的
  `TodoList` / `GoalList`，`createRunRuntime` 建好后同时交给工具集与 `Run`，读到的必然是模型刚写进去的
  那一份），不是从历史里那条 `todo_write` 的入参反推的。
  前端因此删掉两处按工具名读入参的代码：`render.js` 的 `announceTodos`（流式那一份，认
  `todo_write` / `goal_write` 两个名字）与 `renderHistory` 里扫完整段对话取「最后一次 `todo_write`」的
  那一段；`todo-dock.js` 改为听一个 `lk:facts` 事件，待办与目标一起画。
  直接收益是一个真 bug 的修复：**上下文压缩之后 dock 不再凭空清空**——被折进摘要的那条工具调用再也
  扫不到，从前跑任务跑到一半，底下那行「还剩几项」会自己消失。
- `facts` 只在**内容真的变了**时发（每次工具跑完比对一次指纹）：跑十个不改待办的工具不会白刷一次界面，
  服务端也不必写「哪些工具会改这两样」的名单——将来新增一个会写事实的工具，这里不用跟着改。
- **工具行那一行摘要改由服务端随事件下发**：`tool_start` / `tool_end` 多一个 `summary` 字段，
  `history` 快照多一张 `cards`（工具调用 id → 这件事在界面上要用的东西；这张表在下面「前端最后三处…」
  那一条里扩成了摘要 + 路径 + 交付物）。摘要来自工具自陈（core 的
  `summarize(input)`），前端**不再认任何字段名**——从前 `render.js` 里硬编码着 bash→command、
  read/write/edit→path、grep/glob→pattern、todo_write→todos、present→files，加一个工具就要改一次
  前端；而 `job_start` / `subagent_*` / `goal_*` 因为没人记得改，工具行上一直是整坨 JSON。
  `history` 也带上这张表是必须的：只改实时事件会造成「刚跑完显示命令原文，刷新一次变成 JSON」——
  那种不一致用实时事件断言看不出来。
- 体量信号跟着归位：`write` 那行的「N 行」从网页硬编码搬进工具摘要（现在是 `src/a.ts（3 行）`），
  `edit` 同理带上「N 处」。

### Changed

- **前端最后三处按工具名读入参的代码删掉了**，三件事都改成服务端按工具自陈下发：
  1. **「预览文件」入口**：从前是「入参里有 `path` 字段就给」，现在看工具自陈的 `pathOf`。
     换成自陈之后 `read` 漏了声明，读文件那一行的入口**整排消失**——看截图才发现的（验收脚本里量了
     每一行有没有这个按钮），已补上并写了回归测试；`grep` / `glob` 的 `path` 是搜索起点，
     从前点开预览的是一个目录，现在那一行不再有这个按钮（刻意如此，不是漏了）。
  2. **交付物卡片**：从前认 `present` 这个名字并读 `input.files`，现在看工具自陈的 `deliverables`
     ——任何工具只要声明它，界面就照着铺卡片，不必改前端。
  3. **确认卡片上的「改动片段」**：从前认 `write` 这个名字并读 `input.path` / `input.content`，
     现在看工具自陈的 `fileReplacement`；不是整份替换就没有这一节。
  协议上：`history` 快照那张表改名成 `cards`，每项是 `{ summary, path, deliverables }`；
  `tool_start` / `tool_end` 各多 `path` 与 `deliverables`；`approval` 事件与快照里的待确认调用
  多一个 `change`（下一段说的那份算好的对比）。原有的 `summary` 字段一个没少，只是同一行要用的
  东西凑成了一份。
  真起服务 + 假模型 + 真无头 Chrome 在 1280×820 与 460×820 各看过截图：确认卡片上的「改动片段」
  （`−` / `+` 都有）、批准之后的两张交付物卡片、展开 `write` 那一行的「预览文件」按钮都在，
  刷新页面后依然都在；两个宽度都没有横向溢出，交付物卡片也没撑破容器。
- **两份 diff 合成一份**（`web/diff.ts`）：行级 diff 的算法（削公共前后缀 → LCS → 编行号 → 切 hunk）
  原先有两份实现——服务端这份（`feature-history.ts`，逐轮差异）与网页那份（`render.js` 的
  `appendApprovalDiff`，只是「去掉首尾相同的行」的近似）。同一个改动在两个地方长得不一样，连
  「哪一侧是旧」的口径都不同（一个 `-` 是快照里删掉的，一个 `-` 是磁盘上会被盖掉的）。
  现在算法只有一份，两个消费者都按它来：
  - 「历史」面板：逐轮差异照旧（`feature-history.ts` 只留下「读快照、夹路径、按预算拼响应」）；
  - 确认卡片：`change` 从 `{ path, content }` 变成服务端算好的 `ReplacementDiff`
    （`sections` 带 `@@` 段头与两侧行号 + `added` / `removed` + 一句 `note`）。网页不再为了这一节
    去拉一次 `/api/file-content`，也不再自己数行号；`/api/file-content` 仍归文件编辑器用。
  顺手把一处口径说清：统计是**全量**（只显示前面一段时 `+N −M` 仍是整笔改动的数），
  而「只比较了前 N 行」与「逐行相同」不再混为一谈——截断掉的那部分可能正是唯一不一样的地方，
  从前那种情形会报「没有差异」。新增 `test/diff.test.ts`（13 条）钉住这些口径，此前这套算法
  一条测试都没有。
- **同一个档位反复设不再重复广播**（值没变（`Object.is`）就不通知订阅者）。`setApproval` / `setPlanMode` / `setStyle` / `setCompaction` 从前一律广播一条
  `modes` 事件，于是在另一个标签页把档位设成**同一个值**、或者界面上重复点同一档时，所有订阅者都要
  白重绘一遍。现在内核那份照样设置（它自己也有同样的判断），只有值真的变了才广播。
- 重试等待时间打成人话（`上游不可用，30.0 秒后重试…`，超过一分钟写「5 分钟」）：内核那一侧
  `Retry-After` 不再被我们自己的退避上限夹住，等待可能是几分钟，`300000ms` 要心算才看得懂。

- **`web/server.ts` 的集合级路由改成表驱动**（同一套注册表思路）：`directoryRoutes`（选目录本身，
  排在那道 409 关卡之前）与 `workspaceRoutes`（会话、排序、文件预览）各自声明「精确路径 + 允许的方法
  + handler」，`handleRequest` 只按表跑一遍。买到的三件事：
  1. **`/api/sessions/order` 的顺序依赖消失**：从前靠「把它写在 `/api/sessions/<id>` 那条之前」避开

  完全不同——`Run` 跟着一轮对话走，注册表跟着进程走；它们之间只有一处单向依赖（注册表造 `Run` 并

  `RunRegistry` / `SetSessionCwdResult` 改从 `registry.ts` 出（包内三个取用点已同步）。

  `cwd` / `registry` 的部分，所以能整组搬走；其余那些与目录、会话有关的仍旧留在原处——它们要读写的
  正是那两个可变量。
  顺带把**三处重复组装 `StateResponse`**（`GET /api/state` 与切工作目录的两个响应）收成一个
  `stateResponse(context)`：抄三遍的下场是加字段时漏掉一处，而界面上只表现为「切过目录之后这个字段没了」。

  会被整个重新赋值，捕获对象的话切完之后拿到的还是旧的，而调用点看上去完全正常。

  **之前**返回，因此没选目录时它们照样可用。

  不在那条路上。

  子代理进度表、逐轮快照这四样改由一个工厂 `createRunRuntime()` 一次造好，`Run` 的构造函数从近百行
  接线变成一次调用。理由是「一个会话怎么跑」与「一个 agent 怎么造」是两件事——混在构造函数里之后，
  光看 `Run` 是看不出它究竟装了些什么的。`runs.ts` 842 → 772 行。
  **刻意不抄 CC 的一处**：那边的 `runAgent` 有 18 个位置参数（其中 4 个回调），三份分析报告都把它列进
  「明显不该照搬」；这里改成**一个配置对象**，并按「宿主配置 / 会话档位 / 回调」分了组。
  配置契约（`RunHostConfig`）定义在工厂一侧、`RunOptions` 去 extends 它，因此这个模块**不 import
  `runs.ts`**——反过来的话两者成环（ESM 里类型环编得过去，但属于「现在能跑、改一处就炸」的结构）。

  捕获成布尔值会把「改了开关但子代理还按老规矩压」这种不一致固化下来。
  **对外行为没变**：`RunOptions` 的字段一个不少、可选性也没变，`Run` / `RunRegistry` 的导出面照旧。

### Fixed

- **「历史」面板里展开那一轮会被下一次刷新合上**：列表每次 `refresh()` 都整体重建（打开面板时容器
  从 0 宽变宽、换会话、回滚之后都会刷一遍），而展开状态只活在 DOM 上，于是**打开面板时那次刷新还在
  路上、用户这时点开某一轮**，刷新一落地就把它合上了——看起来像「点了没反应」。
  真机验收时量到的：`.lkx-history-turn` 的 `open` 在 3 秒里 12 次采样全是 `false`，而 DOM 里其实
  已经有 diff 了（第一个文件默认展开，所以差异照样拉下来了）。现在展开状态按会话记着
  （轮次用集合、文件行用「用户最后一次的选择」三态——第一个文件是默认展开的，不留三态就分不开
  「没记录」与「用户收起来了」），重建时恢复。
- **进行中那一轮被画了两遍**：`turn.ts` 在跑工具**之前**就把助理消息推进了 `agent.messages`，所以那一轮
  还没结束时它已经在历史里了；而它的正文与工具行又由 `pending` 快照单独带着。两处都发，界面上就是
  同一个工具行出现两次（一条「未完成」来自历史、一条「运行中」来自 pending），助理正文也跟着重复一遍。
  现在 `Run.messages()` 把**末尾那条带工具调用的助理消息**投影掉——工具结果一跑完就紧跟着推一条
  `tool` 消息，所以「末尾 + 带工具调用」只可能是「工具还没跑完」的那一条；不带工具调用的不受影响
  （它要等流式收完才入历史，那时 `pending` 里只是半截正文，两者不重复）。
  **这是看截图发现的**，断言完全查不出来：服务端两条都发是「对」的，重复发生在渲染层。
  验收方式：假模型 + 真服务 + 真无头 Chrome，探针量「名字为 bash 的工具行出现了几次」——
  修之前 2、修之后 1（1280 与 460 两个宽度都量过并看过图）。
- **确认卡片上 `edit` 的改动预览一直是空的**：`render.js` 的 `describeApprovalInput` 读的是
  `old_string` / `new_string`，而工具的真正入参是 `edits: [{oldText, newText}]`——两个字段名压根
  不存在，于是「将要修改」那一段每次都退回成末尾那行 JSON，改了什么完全看不见。现在按真实入参
  渲染，一处以上会逐处编号，超过三处折叠。

  重连会从快照里拿回服务端攒的总数；最近一轮的数字没了时退成「本会话 N 轮 · 缓存 R%」，而不是整块消失。

  确认卡与输入框共用这一个值，所以一起变），范围 560px–主干区 −48px、最多 1600px；双击复位**到最长**，
  键盘 ←/→ 每次 40px；窄屏隐藏。启动时直接拉到主干区允许的上限（窗口变大也跟着变），用户自己拖窄之后
  就以他的选择为准。拖柄贴在卡片里侧（距描边 3px），不悬停时完全隐形。不落盘，刷新回最长。

### Fixed

- **对话内容与输入框现在同宽同轴**：工具确认卡与方案评审卡是**直接挂在对话流上**的（不像消息那样包在
  `.turn` 里，那个才有 880px 上限），所以它们一直通栏、与输入框错位。现在 `.transcript > *` 统一用
  `--content-width`，消息 / 工具卡 / 确认卡 / 方案卡 / 输入框五者同宽同轴（实测都是 854px 宽、
  中心 783、左边缘 356）。顺带：对话区要滚、输入框不滚，滚动条会让内容列窄 10px——现在对话区
  `scrollbar-gutter: stable both-edges`、输入框按实测的 `--scrollbar-width` 同步预留，两边可用宽度一致。
- **Windows 上命令输出的乱码**：子进程输出原先是 `chunk.toString("utf-8")`，而 `cmd.exe` 的内建命令按
  **控制台代码页**写字（中文系统是 GBK）——`'cat' 不是内部或外部命令` 就变成一片替换字符（使用者截图里的
  乱码）。现在统一走 `decodeProcessOutput`：先严格按 UTF-8 解，解不动再按系统代码页（zh→gbk、
  ja→shift_jis、ko→euc-kr、ru→windows-1251，兜底 gbk / windows-1252），候选一律用 `fatal` 以便挑一个
  **能完整解开**的；谁也解不开时退回宽容 UTF-8，不抛错。bash 工具与 Web 终端都改用它，并且
  **攒够整段再解**（按块解会在块边界截断多字节字符，这个老问题一并修掉）；钩子脚本的输出同理。
  实测：GBK 字节 → `'cat' 不是内部或外部命令`（此前是一串替换字符）。
  新增测试：`decodeProcessOutput` 的 UTF-8 / 空输入 / Windows GBK / 不可解字节不抛错，
  以及 bash 工具的「系统代码页的输出不会变成乱码」（断言输出里没有替换字符，跨语言环境都成立）。

### Changed

- **「上下文压缩」改到输入框右下角，并包成药丸**：原来它是贴在 textarea 上方的一行小字，现在放进动作行、
  位于状态与「发送」之间（也就是输入框的右下），外形是药丸——`--radius-pill` + `--surface-3` 底 + 1px 描边、
  3px/10px 内边距、26px 高。文案长了单行省略，完整文案在 `title` 里；窄屏（460）下它缩到 69px 也不挤，
  动作行与页面都不溢出。失败提示仍留在对话末尾（那是要动手处理的事）。
- **内层圆角改成同心**（内层 = 外层 − 两层之间的间距），并且用 `calc()` 从外层 token 推导，改外层半径或
  间距时会自动跟上：
  - 侧栏（32）里的会话行 24 → **15**（`calc(var(--radius-xl) - var(--space-4) - 1px)`，间距 17）、
    侧栏底部卡 28 → **19**（`- var(--space-3)`，间距 13）；
  - 面板（32）里的设置卡片、终端输出区与输入行、评审报告框 24 → **15**；
  - 体检的行原来是 16（列表容器还自带 8px 内边距，间距 25 → 同心只有 7，很难看）：去掉容器内边距后
    间距回到 17，同心半径 **15**；
  - 设置面板的容器 `.lmk-settings` 去掉多余的 12px 内边距（面板体已经留了 16px）——留着的话卡片被推到
    29px 外，同心半径只能落到 3px。
  验收：`lkx-concentric-probe.mjs` 对每对「有底色+圆角」的外层/内层量「外半径 − 间距」与实际内半径的差，
  > 2px 就报出来；六个标签 + 侧栏都是**全部同心**。高度 < 48px 的扁内层不适用同心（否则会逼出
  3–7px 的怪异小圆角），这条豁免写在探针与 AGENTS.md 里。
- **面板标签按「看的顺序」重排**：`文件 → 历史 → 评审 → 终端 → 体检 → 设置`（原来是 文件 / 历史 /
  终端 / 评审 / …）。读代码 → 看改了什么 → 评审这些改动 → 需要时跑命令 → 体检 → 设置，
  同类相邻；「设置」这种偶尔才开的仍在最后。
- **颜色补上层次**：原来只有一路粉，三栏（侧栏 / 主干 / 面板）几乎是同一个色，所以「不够有层次」。
  - 补齐 MD3 的 secondary（淡紫）与 tertiary（暖橙）两套色相角色：品牌标记用 primary→tertiary 渐变，
    侧栏里**非当前工作区**的分组标题用 secondary 色相（当前那组是 primary，一眼分出「我在哪」），
    诊断的警告色归到 tertiary 色相。
  - 表面色阶拉大（原来相邻只差几个色值，肉眼是同一块），并让**每一处抬起来的表面各占一档**：
    顶栏 → 侧栏 → 面板 → 输入框，四档各不相同（探针量过：浅色与深色各 5 种互不相同的填充）。
  - 背景色晕收敛到「粉—紫」一族：跨色相叠加（橙 + 粉 + 紫）会调出一块中性灰，在周围粉色的衬托下
    眼睛会把它读成绿的；实测像素并不偏绿（9 个采样点都是 R>G≈B），但叠色本身还是收干净了。
- **界面往 MD3 Expressive 的方向靠了一轮：更大胆的形状 + 更多高斯模糊**。
  - 模糊收成三个档位 token（`--blur-sm 12px` / `--blur-md 20px` / `--blur-lg 30px`，外加
    `--saturate-glass 170%`）：原来各处手写的 `blur(14/16/18/20/24/30px)` 全是逐处调的，同层级的东西
    糊得不一样，看起来就是「脏」。
  - 玻璃面从「侧栏 + 输入框 + 弹窗」扩到**顶栏、右侧面板、行菜单、预览卡、命令菜单、模式弹层、
    确认/方案卡片**；圆角整体加大（卡片 20→24、面板与侧栏底卡 24→28、外层 28→32）。
  - 浅色主题给页面铺了三层极淡的主色/三色/次色晕（radial-gradient，`background-attachment: fixed`）：
    **纯平底色上做高斯模糊等于白做**（糊一块纯色还是那块纯色），有色晕才有东西可糊。窄屏下面板浮在
    侧栏上时最明显——背后的字被真实糊掉。
  - 深色主题**页面仍是纯黑**（这是使用者的明确要求），所以色晕一律透明、玻璃只靠内容从它下面穿过体现，
    比浅色含蓄。

### Fixed

### Added
